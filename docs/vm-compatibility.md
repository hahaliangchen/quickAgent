VM 兼容性按阶段推进

目标是模型写标准 JavaScript，运行时按标准 JavaScript 执行，以 ES2015 为底线，保留已有后续特性。当前仍是 JS 子集，不提前把语言指南改称“完整 ES2015”。每阶段先补测试，再实现，结束时跑定向和全量测试，逐个比较已知失败名称；报告后由用户决定是否进入下一阶段。不启动真实模型，不创建分支或提交。

阶段顺序沿用用户提供的方案：

0. 一致性与真实代码编译的尺子、诊断、预算口径。
1. Map、Set、WeakMap、WeakSet，以及集合快照恢复、内置迭代。
2. 回合内定时器和宏/微任务顺序、挂起恢复、取消。
3. this、函数值调用、原型链、属性描述符、Reflect。
4. Symbol、可迭代协议和进行中迭代的快照。
5. class、extends、super、new.target。
6. 生成器的帧、next/return/throw、yield 处存盘恢复。
7. 异步迭代、异步生成器与存盘恢复（按用户本轮指示提前）。
8. 通用标签模板、正则 y/u、按测量结果补其余内置方法。
9. 清晰列出例外，统一说明与错误时机，再精简提示词。

跨回合、跨天定时任务另行设计。Proxy、类型化数组、WeakRef、eval/Function、尾调用优化、Intl、BigInt、本地文件 ES module 不在当前补齐范围；仍用 host: 导入和 @module。新值和异步状态必须随 Runtime 序列化，不能靠换成外部 JS 引擎丢掉这一能力。

阶段 0 的具体契约

- test262 固定提交及归档 SHA256，源码在仓库外；仓库只放运行器、选择范围、结果基线。[测量说明](../tests/vm/README.md)。
- 最小 assertion harness 只存在测试构建。标准语言缺口不能在测试版悄悄补上；不支持的特性必须继续显现在结果里。当前严格模块模式与 test262 全局脚本、双模式运行不同，明确记录限制。
- 原始模型代码交给 compile_with_libraries，只编译、不执行、不改写；按来源单独统计，冻结原始 corpus，下一阶段不能更换分母。
- 不支持的 new Map、new Set、WeakMap、WeakSet、this、class 等诊断点名特性与源码行列，替代写法说明语义局限。
- 指令预算由整段累计 1,000,000 改为两次已完成宿主交互之间 1,000,000。只执行 next()、存盘恢复、纯微任务都不刷新；真正 resume 或 resume_action 才开启新段。整段另设默认 30 分钟墙钟期限，包含宿主等待与用户暂停时间，恢复不延长。这个数值是本阶段采用的默认值，未来可按实际任务调整。
- 快照保留剩余指令、段上限、累计执行数、按函数/源码行计数、开始时刻、总时长上限。旧快照缺的新字段采用兼容默认；第一次重新推进旧快照时建立起点。
- INSTRUCTION_BUDGET_EXHAUSTED / PROGRAM_TIME_BUDGET_EXHAUSTED 报告上限、已用量、累计量、位置与最耗指令的源码行。资源错误停止程序、保留输出，让调用方调整编排；不作为普通实现错误自动重放。宿主等并发子调用或执行工具时也受期限约束。中断交互的副作用可能未知，必须核对后再做。

这项预算变更属于行为变更，不能把阶段 0 笼统描述为“不改语义”；其余语言能力留到后续阶段。

阶段 1（集合）已实现并验证，详细结果见 [阶段报告](../tests/vm/REPORT-stage1.md)。集合是独立堆节点；哈希查找缓存与插入顺序分开，缓存不进入快照，元素、删除占位与实时迭代游标进入快照。WeakMap/WeakSet 按约定用强引用对象键、不提供枚举和 GC 可观察性。内置迭代覆盖 for…of、展开、数组解构、Array.from、Object.fromEntries 与 Promise 组合方法；forEach 回调使用可挂起的普通 VM 帧。原型、this/thisArg、自定义 Symbol.iterator 仍留在阶段 3/4。

阶段 2（回合内定时器）已实现并验证，详细结果见 [阶段报告](../tests/vm/REPORT-stage2.md)。setTimeout/setInterval 保活，queueMicrotask 与 Promise 共用 FIFO 微任务队列，微任务先于定时器回调。快照保留绝对到期时间、回调、参数与闭包；恢复后过期 interval 只触发一次。宿主等待同时覆盖子调用、最近定时器、总期限及停止条件，终止回合也清理保存作用域的程序。实际派发到期计时器刷新指令段，纯微任务不刷新，整段墙钟期限仍包含等待与暂停。数字句柄不是 Node Timeout，不提供 ref/unref/refresh 或跨回合调度；阶段 3 第一部分补了 bind/箭头回调的接收者保留。新增 21 项测试全过，主程序失败集合仍是原来的 29 项。

阶段 3 第一部分（this 与函数调用）已实现并验证，见 [阶段报告](../tests/vm/REPORT-stage3a.md)。普通函数采用严格 this，箭头函数捕获词法 this；call/apply/bind、计算/可选/括号/展开调用保留正确接收者和求值顺序。绑定函数、接收者和参数随堆存盘并参与 GC；回调 thisArg、Promise、工具及定时器可挂起恢复。新增 19 项测试全过，VM 261 通过，主程序 587 通过且失败集合仍是原 29 项，固定 test262 407 → 431 通过、旧通过项无退步。另修正刚重启时 MCP 过期测试减 Instant 两小时导致进程终止的问题。

阶段 3 第二部分（原型链与普通构造）见 [阶段报告](../tests/vm/REPORT-stage3b.md)。对象有可序列化的原型链接；Object.create/getPrototypeOf/setPrototypeOf、继承属性访问、方法接收者、普通函数 new、绑定构造与实际原型链 instanceof 已接通。内置构造器及 prototype 是每个 Runtime 自己的对象，覆盖和删除方法会生效，继承内置原型不授予 Map/Date 等内部槽。原型独有引用参与 GC，构造函数挂起恢复保留实例。新增 23 项测试全过，VM 284 通过；固定 test262 431 → 713 通过，旧通过项无退步。程序指南与库定义已同步。属性描述符、用户 getter/setter 和 Reflect 留待第三部分；不能称阶段 3 整体完成。

阶段 3 第三部分（属性描述符、getter/setter 与 Reflect）已实现并验证，见 [阶段报告](../tests/vm/REPORT-stage3c.md)。数据/访问器描述符、完整性级别、数组 length 约束和 Reflect 13 个方法接通；用户访问器走可挂起的普通 VM 帧，参与 GC 和快照。新增 34 项测试全过，VM 318 通过；主程序 644 通过，失败集合仍为原 29 项。固定 test262 713 → 770 通过且原通过项无退步。额外原型选集 344 → 653 通过，但比较器仍报告 1 项旧误通过：不支持 Object.create 描述符时提前抛出的 TypeError 曾掩盖脚本顶层 this 与模块环境的差异；没有修改旧基线或静默豁免。另测描述符/Reflect 3804 项，1864 通过，保留所有实际失败与拒绝。阶段 3 的约定范围已完成，不代表完整 ES2015：Symbol、自定义可迭代协议、class/new.target 仍按后续阶段推进，部分原生数组读取尚需先 Array.from 物化访问器，宿主 JSON 边界拒绝未物化的访问器。

阶段 4（Symbol 与同步迭代协议）已完成，见 [阶段报告](../tests/vm/REPORT-stage4.md)。Symbol 身份、注册表及不会与普通字符串碰撞的属性键编码进入快照；for-of、展开、解构、Array.from、集合构造、Object.fromEntries 和 Promise 组合方法统一读取 Symbol.iterator，并在消费中断时关闭迭代器。next/return 和循环体 await 的帧、缓存方法、游标与闭包可经 GC/存盘恢复。新增 37 项 VM 测试全过，VM 355 通过；主程序 681 通过，失败仍为原 29 项，名称无变化。固定 test262 770 → 893 通过；四组旧选集均无原通过项退步。新增 Symbol/迭代选集 957 项为 348 通过、517 拒绝、13 运行失败、79 跳过。Node 对照 32 段有 31 段一致，1 段对象 rest 排除键的 getter 次数差异按规范保留，未改 VM 迎合本机 Node；验证期间另有两次访问异常退出，重跑完成，根因未定，均记录在报告。Symbol.asyncIterator 仅提供键，异步迭代、生成器、class、新增 species 等仍留后续阶段。


阶段 5（class、extends、super 与 new.target）已实现并验证，见 [阶段报告](../tests/vm/REPORT-stage5.md)。类声明/表达式、默认/显式构造、实例/static/计算方法和访问器、派生 this 初始化规则、home object 与有效 new.target 接入普通堆/可挂起帧；Error 和既有内置类型子类保留槽位。51 项新测试全过，VM 406 通过；主程序全量 732 通过、29 失败，失败名称与阶段 4 完全相同。五组既有 test262 选集无原通过项退步；固定选集 893 → 900 通过，但开放语法后暴露的运行缺口也如实保留。类专项 8636 项为 1150 通过、1349 拒绝、107 运行失败、6030 跳过，主要剩余运行缺口是名称推断、异步宿主边界和部分内置能力。Node 对照 44 段中 41 段一致，三处求值顺序差异按规范判断保留原始非零结果；本轮全量曾发生一次根因未定的 STATUS_ACCESS_VIOLATION，同一二进制重跑完整结束，未掩盖该异常。公有/私有字段、static 块、动态 Function/eval、生成器、异步迭代和 species 等不在本阶段完成范围。


阶段 5 补充修复已完成，见 [报告](../tests/vm/REPORT-stage5fix.md)。Promise 本地回调统一走正常调用入口，修复误入 JSON 分支、类检查/home object/转换挂起不一致；测试设施补齐 Test262Error 原型链。匿名函数/箭头/类名称推断扩展到绑定、赋值、参数/解构默认值和对象属性，保留 UTF-16。新增 toExponential，回调诊断保留注册源码位置。32 项新回归全过，VM 438 通过；主程序 764 通过、29 失败，失败名称与阶段 5 相同。六组 test262 均无旧通过项退步；固定 900 → 924 通过，类专项运行失败 107 → 4，余下四项属于动态 Function 限制。Node 22 段对照有一处计算属性的类 static name 差异，按规范保留原始非零结果。历史访问异常已找到 dump，并在核对原二进制哈希后定位到 JSON BTree 插入指令，但缺少可靠后续调用链，根因仍未确认，不宣称修复；本轮完整验证未再异常退出。


阶段 6（同步生成器与存盘恢复）已完成，见 [阶段报告](../tests/vm/REPORT-stage6.md)。支持 function* 声明/表达式、对象和类生成器方法、yield/yield*、next/return/throw 与既有同步迭代消费者。生成器的局部变量、闭包、this/home object、异常处理器和 finally 待完成值随 Runtime 保存；开始前、yield、宿主调用中和完成状态均有恢复测试。新增 47 项回归全过（46 项 VM，含 10 项存盘测试，另 1 项宿主集成），VM 484 通过；主程序 811 通过、29 失败、23 忽略，失败名称完全不变。七组既有 test262 选集无旧通过项退步，固定选集 924 → 980 通过。生成器专项 703 项为 516 通过、170 拒绝、8 运行失败、9 跳过；运行失败保留为动态 GeneratorFunction 限制。Node 对照 34 项中 33 一致，1 项默认参数改变原型的差异按规范保留。补齐了 SWC 丢失解构尾部空位的兼容修复。编译与测试避开本机逻辑处理器 8、9，仅为临时硬件绕行。异步生成器与异步迭代、类字段和 arguments 等仍留后续阶段。


阶段 7（异步迭代、异步生成器与存盘恢复）实现见 [阶段报告](../tests/vm/REPORT-stage7.md)。支持 async function*、对象/类 async 生成器方法、for-await、异步 yield* 与 Promise 请求队列。队列、await、catch/finally 和宿主调用中的帧参与 GC 并保存恢复；测试明确断言快照包含多个待完成请求。Await 的 thenable 同化和 Promise.constructor 访问保持可观察顺序，同步迭代器回退不增加多余微任务；一般 Promise.resolve/executor 同化仍未完整开放。逐项验证记录见 [stage7-validation.json](../tests/vm/stage7-validation.json)。
