# Linux 命令的工作区写入限制

Linux 的“工作区内修改”模式使用系统 PATH 中工作区外的 `bwrap`（Bubblewrap）执行 `run_program`、`run_project_script` 和 `install_dependencies`。命令及其子进程继承相同的挂载限制。工作区可写，`/tmp` 是进程私有的临时文件系统，宿主其他文件通过只读挂载访问。项目路径和工作目录按真实路径检查；不允许把 `/` 作为可写工作区。

“执行前询问”模式保留原有审批，获批后 Linux 命令仍使用相同限制。“完全权限”不使用此限制。非 Linux 系统保留原有权限行为：工作区模式不允许运行命令，获批的命令未受此 Linux 沙箱保护。

此模式只约束上述受限进程的直接文件系统操作，**不隔离读取、网络、浏览器、HTTP 工具或其他独立能力**。已有硬链接可能让工作区中的路径与外部文件指向同一对象；宿主可访问的网络服务及 Unix 套接字也可能代表额外权限。因此不能把它当作处理不可信代码的完整安全边界。插件的外部命令工具尚未接入，受限模式会拒绝它们，而不是不受限地运行。

沙箱策略来自 Agent 会话权限；直接调用独立 MCP 服务的外部客户端不经过该会话权限链，不能假定同样受此限制。

在 Ubuntu 上安装 `bubblewrap`，并确保系统允许它创建需要的命名空间。缺少 runner、启动失败或隔离配置失败时，受限命令失败，不会退回宿主执行。系统 AppArmor 策略可能阻止命名空间；请检查发行版的 Bubblewrap 配置，不要为了让它启动而随意关闭系统安全策略。

执行目录在启动沙箱后重新切换到项目真实路径，避免 `/tmp` 下的工作区写入落在临时层。后台项目进程只复用相同隔离边界的已有进程。项目工具的原有进程组终止与取消机制仍然生效。

回归测试：`cargo test process_sandbox::tests`。Linux 上如系统的 Bubblewrap 可用，还会实际检查相对路径写入、子进程写入、外部路径写入被阻止与临时目录；缺少 Bubblewrap 或命名空间不受支持时会跳过该集成测试并说明原因。
