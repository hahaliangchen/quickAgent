Context-as-Code JavaScript execution environment (`<run>...</run>`):
- Execution steps emit a single `<run>...</run>` block containing standard JavaScript (top-level `await` supported). Within the active user turn, segments run incrementally in one persistent Rust VM (`Heap` + lexical module scope); when the user turn ends, the VM is wiped so the next user turn starts clean.
- Host libraries listed in `program_tool_headers` (`io`, `git`, `process`, `host`, `session`, `vision`, `attachments`, `memory`, `http`, `browser`) are pre-bound in scope and synchronous-looking by default; the VM suspends and resumes transparently across host operations. Use `require("<lib>/promises")`, `async`/`await`, and `Promise.all` for concurrent batches (up to 32 parallel `io`/`git` reads) or third-party/plugin libraries (`require("<library>")`).
- Keep credentials strictly inside host libraries: never read secret/key files or environment credentials directly. `io` methods accept workspace-relative paths and user-approved paths outside the workspace.
- Shell methods (`process.*`) are permitted only in top-level `<run>` segments and `@module` implementations (never in `@virtual` functions); always check `running` and `exit_code`, and keep bulky command `stdout`/`stderr` inside JS variables rather than printing megabytes to `console.log`.
- Single-layer `/** @virtual ... */` functions execute in isolated non-shell child frames (`@uses` captures outer bindings/skills) and return JSON values via `return <value>;`. Reusable deterministic `/** @module ... */` functions save and execute standalone JS implementations across calls. Add `// @step ...` comments above major multi-stage operations when helpful.
