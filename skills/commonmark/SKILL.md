# CommonMark

示例在与本文件同目录的 `examples.json`：CommonMark 规范 0.31.2 的 103 个示例，涉及反斜杠转义、ATX 标题、段落、引用、围栏代码、行内代码、强调、链接和列表。每条是 `{"section", "markdown", "html"}`，`html` 是规范要求的完整输出，块标签之间带换行，比较时可以忽略块标签两侧的空白。写测试时读取这个文件，按 `section` 取需求范围内的条目逐条比对。

要点：

- 先分块，再解析行内。逐行确定块结构（标题、段落、列表项、引用、围栏代码），再解析段落和标题里的文字。代码块和行内代码的内容只转义，不做行内解析。
- 列表项内容的起始列 = 标记宽度 + 标记后的空格数（1 到 4 个，多于 4 个按 1 个算）。后续行缩进到这一列才属于这一项，嵌套列表也按这个规则判断。
- 行内的优先级：反斜杠转义和行内代码先于强调和链接；链接文字里可以有强调，但不能再有链接。
- 强调用规范附录“A parsing strategy”里的分隔符栈（delimiter stack 和 process emphasis），不要用正则成对替换，否则嵌套、相邻和不成对的情况会出错：
  - 一串连续的 `*` 或 `_` 是一个分隔符串。左侧翼：后面不是空白，并且后面不是标点，或者后面是标点而前面是空白或标点（行首行尾算空白）。右侧翼左右对调。`*` 左侧翼能开、右侧翼能闭；`_` 能开还要求不是右侧翼或前面是标点，能闭还要求不是左侧翼或后面是标点。
  - 从左往右找能闭的分隔符，再往回找最近的、字符相同且能开的分隔符。两边都剩至少 2 个时生成 `<strong>`，否则生成 `<em>`；两边各扣掉用掉的个数，夹在中间的分隔符全部作废，剩下的继续配对。没有配对的分隔符原样输出为文字。
  - 两边中有一边既能开又能闭时，若两串原始长度之和是 3 的倍数，就不配对，除非两串长度都是 3 的倍数。
  - `[` 也入栈。遇到 `]` 且后面紧跟 `(地址 "标题")` 时生成链接，先在链接文字内部单独配对强调，外面的分隔符不和里面的配对。
- 输出：文字里的 `&`、`<`、`>`、`"` 转义为 `&amp;`、`&lt;`、`&gt;`、`&quot;`。围栏代码输出 `<pre><code>`，有信息串时加 `class="language-信息串第一个词"`，内容以换行结尾。有序列表起始号不是 1 时加 `start`。列表项之间有空行，或某一项直接包含的两个块之间有空行，这个列表就是松散的，各项的文字包在 `<p>` 里；否则不加 `<p>`。

示例出自 CommonMark Spec 0.31.2（John MacFarlane，CC BY-SA 4.0），期望输出用 micromark 4.0.2 生成并核对。
