# 按规格写测试

1. 动手前先找规格：需求里点名的标准（如 CommonMark、某个 RFC），已加载技能附带的规范和示例文件，工作区里的规范、示例和样例数据。
2. 规格里写明了做法的部分（算法、优先级、处理顺序），照规格的做法实现，不凭印象另写一套。
3. 测试用例从规格和需求里取，不照着实现写。除了常见情况，专门覆盖边界：嵌套、相邻、交错、空输入、转义、看起来像但不该匹配的输入。
4. 规格附带示例文件时，让测试直接读取它逐条比对，只挑需求范围内的条目；失败时打印输入、期望和实际输出。
5. 实现后跑全部测试。不过的修实现，不改测试或期望值去迁就实现；确实超出需求范围的条目，写明原因后跳过。
6. 交付时说明用了哪些规格材料、通过多少条、还有哪些没过及原因。
